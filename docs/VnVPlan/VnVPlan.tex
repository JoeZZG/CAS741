\section{General Information}

\subsection{Summary}

Trajecto is a command-line simulator for the motion of a single charged particle
in prescribed electric and magnetic fields. The user provides the particle
parameters like mass, charge, location and velocity, a set of rectangular field
regions with piecewise-constant electric field information and magnetic field
information, a final time, and a detector line with its position. Trajecto
computes the time evolution, including position over time and velocity over
time. It then reports sampled trajectory data and detector information.

\subsection{Objectives}

This VnV plan aims to provide practical evidence that \progname{Trajecto} matches
the SRS, by:
\begin{itemize}
  \item checking the SRS is internally consistent from assumptions to models and
  then requirements;
  \item verifying the implementation satisfies the functional requirements; and
  \item evaluating key nonfunctional requirements: accuracy, usability,
  maintainability, and portability.
\end{itemize}

  \item Analyze differences between actual outputs and expected outputs, and refine the program accordingly.
\end{enumerate}

\subsection{Software Validation}

Trajecto is validated by checking whether its outputs match a credible reference
behaviour consistent with the SRS.  We will validate the simulator through:
\begin{itemize}
  \item \textbf{Analytic validation:} for scenarios where a closed-form solution
  exists, compare the reported trajectory and detector-hit results to the
  analytic solution.
  \item \textbf{Physics-based validation:} check that known physical properties
  (e.g., invariants or qualitative behaviours expected under the prescribed
  fields) hold for representative inputs.
  \item \textbf{User-level validation:} confirm that a typical user can run a
  provided example and correctly interpret the reported trajectory data and
  detector-hit result.
\end{itemize}

\subsubsection{Electric-field analytic trajectory}

This test verifies that the electric-field term of the Lorentz force is
correctly implemented (GD3 in the SRS), addressing the gap identified in
issue~\#10.  With $\mathbf{B}=\mathbf{0}$ and $\mathbf{E}\neq\mathbf{0}$, the
equations of motion reduce to constant acceleration, yielding a closed-form
analytic solution.

\begin{enumerate}

\item{T-FR-4\\}

Control: Automatic\\

Initial State:
\begin{itemize}
  \item Clean working directory (no prior outputs).
\end{itemize}

Input:
\begin{itemize}
  \item Particle: $m = 1.0$, $q = 1.0$, $(x_0,y_0)=(0,0)$, $(v_{0x},v_{0y})=(0,0)$.
  \item Region: $R_1 = [-1,3]\times[-1,1]$.
  \item Fields: $\mathbf{E}_1=\langle 1,0,0\rangle$, $\mathbf{B}_1=\langle 0,0,0\rangle$.
  \item Detector: $x_{\mathrm{det}}=2$, $y\in[-0.5,0.5]$.
  \item $t_{\text{final}}=3.0$.
\end{itemize}

Output:
\begin{itemize}
  \item Trajectory (exact analytic solution under constant acceleration
        $a_x = qE_x/m = 1$):
  \[
    x(t)=\tfrac{1}{2}t^2,\quad y(t)=0,\quad v_x(t)=t,\quad v_y(t)=0.
  \]
  \item Detector hit:
  \[
    t_{\mathrm{hit}} = 2.0,\quad (x_{\mathrm{hit}},y_{\mathrm{hit}})=(2,\,0).
  \]
\end{itemize}

Test Case Derivation:
\begin{itemize}
  \item With $\mathbf{B}=\mathbf{0}$ and $\mathbf{E}=\langle 1,0,0\rangle$, the
        $x$-equation of motion gives $\dot{v}_x = (q/m)E_x = 1$ and
        $\dot{v}_y = 0$.  Integrating with zero initial velocity and position
        yields the stated formulas.
  \item The detector hit time follows from $x(t_{\mathrm{hit}})=x_{\mathrm{det}}=2$.
\end{itemize}

How test will be performed:
\begin{itemize}
  \item Run Trajecto with the inputs above.
  \item Parse the sampled trajectory and check max absolute errors:
        $|x(t_i)-\tfrac{1}{2}t_i^2|\le 10^{-3}$ and $|y(t_i)|\le 10^{-6}$.
  \item Verify the reported $t_{\mathrm{hit}}=2.0$ and $y_{\mathrm{hit}}=0$,
        each within tolerance $10^{-3}$.
\end{itemize}

\end{enumerate}

\subsubsection{Multi-region field transition}

This test verifies that the piecewise field-selection logic (DD6, IM1 in the SRS)
correctly switches field values when the particle crosses from one region into an
adjacent region with different field values, addressing the gap identified in
issue~\#11.

\begin{enumerate}

\item{T-FR-5\\}

Control: Automatic\\

Initial State:
\begin{itemize}
  \item Clean working directory (no prior outputs).
\end{itemize}

Input:
\begin{itemize}
  \item Particle: $m=1$, $q=1$, $(x_0,y_0)=(0,0)$, $(v_{0x},v_{0y})=(1,0)$.
  \item Two adjacent regions:
    \begin{itemize}
      \item $R_1=[-1,1]\times[-2,2]$:
            $\mathbf{E}_1=\langle 0,0,0\rangle$, $\mathbf{B}_1=\langle 0,0,0\rangle$
            (field-free).
      \item $R_2=[1,4]\times[-2,2]$:
            $\mathbf{E}_2=\langle 0,0,0\rangle$, $\mathbf{B}_2=\langle 0,0,1\rangle$
            (magnetic-only).
    \end{itemize}
  \item Detector: $x_{\mathrm{det}}=0.5$, $y\in[-1,1]$.
  \item $t_{\text{final}}=4.0$.
\end{itemize}

Output:
\begin{itemize}
  \item \textbf{Detector hit (in $R_1$):}
  \[
    t_{\mathrm{hit}}=0.5,\quad (x_{\mathrm{hit}},y_{\mathrm{hit}})=(0.5,\,0).
  \]
  \item \textbf{Speed invariant after entering $R_2$} (confirms the field switch
        occurred): for all sampled times $t_i > 1$,
  \[
    v_x(t_i)^2+v_y(t_i)^2 \approx 1
    \quad\Bigl(\text{relative drift} \le 1\%\Bigr).
  \]
\end{itemize}

Test Case Derivation:
\begin{itemize}
  \item In $R_1$ ($0\le t\le 1$): no fields, so $x(t)=t$, $y(t)=0$.
        Detector hit at $t=0.5$, $y_{\mathrm{hit}}=0$.
  \item At $t=1$ the particle enters $R_2$ at $(1,0)$ with velocity $(1,0)$.
        In $R_2$, $\mathbf{B}\neq\mathbf{0}$ and $\mathbf{E}=\mathbf{0}$, so the
        magnetic force is perpendicular to velocity and speed is conserved.
        If the field-selection logic correctly switches to the $R_2$ fields, speed
        remains~$1$; if the fields were not switched the particle would continue
        in a straight line with no speed change but incorrect field behaviour.
\end{itemize}

How test will be performed:
\begin{itemize}
  \item Run Trajecto with the inputs above.
  \item Verify $t_{\mathrm{hit}}=0.5$ and $y_{\mathrm{hit}}=0$ (each within $10^{-3}$).
  \item Extract $(v_x,v_y)$ for all sampled $t_i > 1$ and confirm
        $\max_i\bigl|v_x(t_i)^2+v_y(t_i)^2-1\bigr|\le 0.01$.
\end{itemize}

\end{enumerate}

\end{itemize}

Output/Result:
\begin{itemize}
  \item Speed-squared $S(t_i)=v_x(t_i)^2+v_y(t_i)^2$ remains approximately constant for a small $t_i$.
  \item Acceptance criteria: relative drift
  \[
    \frac{\max_i |S(t_i)-S(t_0)|}{S(t_0)} \le 1\%.
  \]
\end{itemize}

How test will be performed:
\begin{itemize}
  \item Run Trajecto and extract $(v_x,v_y)$ from trajectory samples.
  \item Compute $S(t_i)$ and verify drift threshold.
\end{itemize}

\end{enumerate}

  \item User correctly identifies:

  \end{itemize}
\end{itemize}

\end{itemize}

\paragraph{Input-error feedback quality}

\begin{enumerate}

\item{NFR-USE-2\\}

Type: Dynamic, Manual\\

Initial State:
\begin{itemize}
  \item Trajecto runnable.
\end{itemize}

Input/Condition:
\begin{itemize}
  \item Systematic coverage of all input constraints is provided by the automated
        tests T-INV-1 through T-INV-5 (see Section~\ref{sec:inputval}). This
        manual test focuses exclusively on the \emph{quality} of the error message
        visible to a real user.  Choose any one scenario from T-INV-1 through
        T-INV-5 to exercise.
\end{itemize}

Output/Result:
\begin{itemize}
  \item Program rejects the run and prints a clear, actionable error message that:
  \begin{itemize}
    \item names the invalid parameter, and
    \item states the expected constraint.
  \end{itemize}
  \item The message is understandable without consulting the manual.
  \item No misleading trajectory/detector outputs are produced for the invalid run.
\end{itemize}

How test will be performed:
\begin{itemize}
  \item Choose one scenario from T-INV-1 through T-INV-5.
  \item Execute the invalid-input run, inspect the error message, and record
        whether a new user could understand and correct the mistake without
        additional documentation.
\end{itemize}

\end{enumerate}


\subsubsection{Maintainability}


\begin{enumerate}

\item{NFR-MAINT-1\\}

Type: Static, Manual\\

Initial State:
\begin{itemize}
  \item Baseline repository and documents are available.
  \item Original development effort is recorded.
\end{itemize}

Input/Condition:
\begin{itemize}
  \item Apply likely change LC1: ``Add new a feature such that the software support 3 dimension.''
\end{itemize}

Output/Result:
\begin{itemize}
  \item Impact analysis identifies affected artifacts (minimum):
  \begin{itemize}
    \item SRS: assumptions/models/data definitions/instance models,
    \item implementation: state representation, integrator, region logic, detector model,
    \item test suite: update/add system tests and unit tests.
  \end{itemize}
  \item Pass criterion: estimated LC1 effort $< 0.25$ of original development effort.
        The 25\% threshold is justified as follows: the 2D-to-3D extension
        (LC1, \texttt{LC\_3D} in the SRS) requires adding one velocity component
        ($v_z$) and one in-plane field component to the ODE system, and
        generalising the region geometry from axis-aligned rectangles to
        axis-aligned boxes.  The SRS was designed so that these changes are
        localised to the state representation, integrator, region-lookup, and
        detector modules --- the exact artifacts listed above.  Because the SRS
        designates LC1 as a \emph{Likely} change, the design should already
        accommodate it; 25\% is therefore a conservative upper bound for
        tractable, well-scoped changes.
        If the impact analysis shows the actual scope exceeds this threshold,
        the fallback pass criterion is to document every affected artifact and
        provide a written rationale for the excess scope.
\end{itemize}

How test will be performed:
\begin{itemize}
  \item Create a short impact table (artifact $\rightarrow$ expected modifications).
  \item Produce an effort estimate and compute the ratio versus baseline effort.
  \item If the ratio exceeds 0.25, document the reason and assess whether the
        excess scope was foreseeable from the SRS.
\end{itemize}

\end{enumerate}
